# MZ-1500 Sound IDE UI 仕様書 (`docs/specification/ui.md`)

本書は、MZ-1500用サウンドドライバ・MMLコンパイラ向け統合開発環境（IDE）のWebフロントエンドに関するUI仕様・デザインルール・各コンポーネントの挙動をまとめたドキュメントです。機能追加や変更に伴い随時追記・更新します。

---

## 1. デザインコンセプト & テーマ仕様 (Linear Style + Bento Grid DAW Theme)

### 1.1 テーマ概要
プロフェッショナルな最新DAWやモダン開発ツール（Linear等）の洗練されたダークテーマを取り入れ、**長時間作業でも目が疲れないマットダークサーフェス**と**視覚的ヒエラルキーが明確なBento Gridレイアウト**を採用。
背景の方眼グリッドや全面ネオン装飾を廃止し、境界線や静的テキストは落ち着いたニュートラルグレー（`#71717a` / `border-white/[0.08]` 等）を基調とします。操作可能なスライダーのつまみやアクティブなボタン・VUメーターにのみピンポイントでアクセントカラーを発光させ、「どこがクリック・操作可能か」が一目で判別できるプロクオリティのGUIを提供します。

### 1.3 共通コンポーネント規格 & Bento Grid 規約
- **Bento Card**: 各機能モジュールは角丸 `rounded-lg` (8px) の独立カードに格納し、1pxの控えめなボーダー（`border-white/[0.08]` または `#3C3C3C`）で整理。
- **入力要素の高さ**: ボタン・セレクト・入力欄は `h-6` (24px) 〜 `h-7` (28px) で統一。
- **自照式・アクティブ表現**: ボタンがアクティブ時のみ背景とボーダーがアクセントカラー（クリアブルー `#00A8FF` 等）で発光し、非アクティブ時はダーク背景に溶け込む。
- **スライダー**: トラック背景は極細のダークグレー、つまみ（Thumb）のみが鮮やかなクリアブルー（`#00A8FF`）に発色し、マウスホバー時にグローを強調。
- **グラフキャンバス**: 不要な背景グリッドやグラデーション塗りを廃止し、極薄の目盛り線と鮮明な折れ線・操作ノードで構成。

## 2. 画面レイアウト構成

FlexboxおよびCSS Gridを活用し、解像度変化に追従するペイン分割レイアウト。

```
+---------------------------------------------------------------------------------+
| HEADER: アプリ名 (MZ-1500 IDE) | アクション群 (BUILD, PLAY, STOP, MZT) | [HIDE PANE] |
+---------------------------------------+-+---------------------------------------+
| LEFT PANE (中央ペイン / 可変幅 20%〜100%): |S| RIGHT PANE (開閉式 / タブ切り替え):    |
| +-----------------------------------+ |P| [📊 TRACK] [∿ TONE] [📈 VOL] [↗ PITCH] |
| | [EXPLORER] | MMLエディタ           | |L| [⚙ SETTINGS]                          |
| +-----------------------------------+ |I| - トラックモニタ & 各エディタ & 設定    |
| | BOTTOM: システムコンソール          | |T|                                       |
| | (ビルド・エラーログ / READY.)      | | |                                       |
| +-----------------------------------+ | |                                       |
+---------------------------------------+-+---------------------------------------+
```

### 2.1 左右ペインスプリッター (リサイザー) & 開閉トグル
- **ドラッグ操作による比率変更**: 左右境界バー（当たり判定 10px / 見た目 4px）をマウスドラッグすることで、20%〜80% の範囲で自在に幅をリサイズ可能。
- **堅牢なイベント制御**: `onMouseDown` 時にネイティブイベントリスナーを即座に登録し、ドラッグ中の全画面オーバーレイにより Monaco Editor のマウス奪取・テキスト選択を完全に防止。
- **視覚的フィードバック**: 通常時はボーダー色、ホバーおよびドラッグ中はQDブルー（シアン発光）に変化。中央にハードウェア風の点線グリップを表示。
- **ダブルクリックリセット**: スプリッターバーをダブルクリックすると即座に 50%:50% の初期比率に復帰。
- **右ペイン開閉トグル (`[HIDE] / [PANE]`)**: **MMLエディタタブバーの最右端**に配置（左端のエクスプローラー開閉ボタンと左右対称の配置）。ワンクリックで右ペインを非表示にしてエディタエリアを全幅（100%）に最大化可能。もう一度押すと直前の分割比率で即座に復帰。

### 2.2 エクスプローラースプリッター (左ペイン内リサイザー)
- **幅リサイズ (140px〜460px)**: エクスプローラーとMMLエディタ間の縦境界バーをドラッグして幅を自在に伸縮可能。ダブルクリックで標準幅（240px）にリセット。

### 2.3 エディタ下部スプリッター & タブ化パネル (上下リサイザー & PROBLEMS / CONSOLE タブ)
- **左ペイン全幅**において、[Monaco Editor (+ エクスプローラー)] ⇔ [下部タブパネル (PROBLEMS / CONSOLE / KEYBOARD)] の境界に水平スプリッターを配置 (2026-09-06: 下部タブパネルはエクスプローラー領域の下まで含む左端からの全幅表示に拡大)。
- **タブ切り替えによるエリア集約**:
  - 従来上下2段だったコンパイルエラー（PROBLEMS）とシステムコンソール（CONSOLE）をタブコンテナとして統合。
  - 将来的に別エリア（逆アセンブラ、メモリマップ、波形プレビューなど）を同エリアへシームレスに追加可能な拡張スロット構造を採用。
- **マウスドラッグによる高さ変更**:
  - エディタ ⇔ 下部タブパネル境界をドラッグし、高さを 60px〜480px で自在に伸縮可能（ダブルクリックで初期高さ 160px にリセット）。
  - ドラッグ中は全画面オーバーレイで `cursor-row-resize` を捕捉し、Monaco Editor のイベント奪取を防ぎスムーズに上下リサイズ。
- **折りたたみトグル (`ChevronDown` / `ChevronUp`) (2026-09-06 追加)**:
  - 下部タブバー右端のボタン (タブ選択に依存せず常時表示) で下部エリア全体を折りたたみ可能。折りたたみ時はタブバーのみ (28px) を残し、高さリサイズ用スプリッターは非表示化。
  - もう一度押すと折りたたみ前の高さに即座に復帰。

## 3. コンポーネント詳細仕様

### 3.1 ヘッダー領域 (`Header`)
- **背景デザイン**: MZ-1500実機およびQD（クイックディスク）ドライブの象徴である**QDテクニカル方眼グリッド背景（主線48px / 副線12pxのシアン複線グリッド）**を適用。
- **ロゴ**: 
  - 左端に実機公式デザイン準拠の **MZ-1500 ベクターSVGロゴ**（[`src/assets/mz1500logo.svg`](../src/assets/mz1500logo.svg): 縦3本バーM、シャープなZ、中空アウトライン1500）を配置（高さ `h-5`）。
  - ロゴ右横にダークグレー角丸の `Sound IDE` バッジ（`bg-[#383838] border-[#484848]`）を配置。
  - サブタイトル: `SOUND DRIVER & MML COMPILER`（区切り線付き）。
- **トランスポートアクションボタン**:
  - `🔁 LOOP`: MMLの `L` コマンドによる無限ループの有効/無効トグルボタン（自照式LEDランプ付き、デフォルト: **ON**）。OFF時は曲末尾または1周で再生停止。
  - `▶ PLAY / STOP / PLAYING`: **アクティブタブのMMLソースを `MmlCompiler` でコンパイルし、成功時のみ `Player` で再生開始**する。
    - **トグル動作**: 再生中に押すと即座に停止（`handleStop`）。
    - **ショートカットキー**: `Ctrl + Enter`（Mac: `Cmd + Enter`）でグローバルおよびMonaco Editor内から即座に再生/停止トグルが可能。
    - 再生中は自照式シアン発光パルスアニメーションを表示。
    - **エラー時フィードバック (2026-09-06 追加)**:
      - コンパイルエラー時や再生失敗時は、PLAYボタンが一時的（約900ms間）に**赤色背景・赤枠・赤色テキスト（`bg-red-950/70 text-red-300 border-red-500 shadow-[0_0_12px_rgba(239,68,68,0.5)]`）に変化し、シェイクアニメーション（`animate-shake`）とともに `FAILED` と `AlertCircle` アイコンを表示**して直感的な失敗フィードバックを即座に提示。900ms後に通常のPLAYボタン表示へ自動復帰。
    - **コンパイル連動 & 自動タブ遷移 (2026-09-06 強化)**:
      - エラーがあれば再生せず、**下部パネルの `PROBLEMS` タブを自動的にアクティブ化**し、下部パネルが折りたたまれていた場合は**自動展開**してエラー一覧を表示（`KEYBOARD` や `CONSOLE` タブ選択中での再生不能の見失いを根本防止）。同時に `CONSOLE` にも診断 (`[BUILD] ERROR/WARNING 行:桁 - メッセージ`) を出力。成功時は経過秒・トラック数・ループ状態をコンソールへ出力。
    - **演奏終了**: ループ OFF の曲が自然終了したら `isPlaying` を解除し、コンソールに `Playback finished.` を出力。
    - **演奏エンジン**: `SETTINGS` タブの `PLAYBACK ENGINE` で `Z80 DRIVER`（既定・2026-09-06 変更）/ `SOURCE INTERPRETER` を切替可能（§3.8）。切替は次回の PLAY から適用。
  - `■ STOP`: 再生停止ボタン（保持）。
  - `EXPORT PLAYER (.qdf)`: アクティブタブのMMLをコンパイルし、**実機演奏プレイヤー入りQuickDisk（QD）用イメージ（`.qdf`、81,936 バイト固定）を生成してダウンロード**する。
    - ファイル名は `#TITLE`（ASCII 正規化・最大 16 文字）を優先し、未設定時はアクティブファイル名。
    - QD ヘッダのロード / 実行アドレスは `0x1200`（MzSD ドライバ + MZSD 楽曲データを配置）。形式仕様は [`quickdisk_export.md`](./quickdisk_export.md) を参照。
    - コンパイルエラー時はダウンロードせず `PROBLEMS` パネルへ自動誘導（タブを自動アクティブ化＆折りたたみ解除）。

### 3.2 MMLエディタ & 下部タブパネル (`MmlEditor.tsx`, `FileExplorer.tsx`, `CompileErrorPanel.tsx`)
- **左ペイン配置**
- **ファイルエクスプローラー (`FileExplorer.tsx`)**:
  - 左端に折りたたみ可能なツリービューサイドバー（幅 240px）を配置。
  - **エクスプローラー開閉トグル**: タブバー最左端のアイコンボタン（`PanelLeftClose` / `PanelLeftOpen`）で表示/非表示を切替可能。
  - **Sample MML（プリセット・2026-09-07 より `samples/` フォルダ連動）**: プロジェクトルートの `samples/` 配下の `*.mml` を Vite `import.meta.glob`（`?raw` / eager）でビルド時に全件取り込み、**実フォルダ構造そのまま**のツリーとして表示（フォルダは初期展開）。クリックでエディタのタブに即時展開され、BUILD/PLAY でそのまま試聴できる。ユーザーは `samples/` にファイル・サブフォルダを追加するだけで SAMPLE MML ツリーへ自動反映され、`npm test` により samples/ 配下の全 .mml がエラー・警告ゼロでコンパイルできることが自動検証される。中身の無いダミーだった `demos/`・`templates/` は本変更で廃止。
  - **`samples/mml_reference/`（ユーザー MML サンプル置き場・2026-09-07 新設）**: 自作 MML を追加するためのデフォルトフォルダ。サブフォルダの作成も可。使い方は同梱 `README.md` を参照。
  - **`samples/classics/`（著作権フリー古典楽曲集）**: パブリックドメインの古典楽曲 5 曲を .mml 実ファイルとして収録（旧 `src/data/sampleMmlSongs.ts` の TS 組み込み文字列からの移行）。全曲とも全トラック先頭に `L` を配置した「曲頭永久ループ」構成で、初期化コマンド（音量・音色等）は `L` より後に記述するためループ復帰時も音色/音量が復元される。classics/ 配下の作法規約（全トラック `L` 宣言 / BEEP トラックの音量コマンド禁止 / FM 使用時 `#OPM ON` 宣言 / トラックテーブルの loopOffset == dataOffset）を `src/data/__tests__/sampleMmlSongs.test.ts` で自動検証。収録曲は以下の 5 曲:

    | ファイル名 | 曲名 / 原曲 | 使用音源・構成 |
    | :--- | :--- | :--- |
    | `classic_fur_elise.mml` | エリーゼのために / L. v. Beethoven (1810) | PSG ×3（P1メロディ / P2アルペジオ / P3低音保持） |
    | `classic_ode_to_joy.mml` | 歓喜の歌（交響曲第9番）/ L. v. Beethoven (1824) | BEEP メロディ（音量指定なし）+ PSG ×2 + N1 ノイズドラム |
    | `classic_menuett_g.mml` | メヌエット ト長調 / C. Petzold (1725頃) | PSG ×2（メロディ + 分散和音ベース） |
    | `classic_pachelbel_canon.mml` | カノン ニ長調 / J. Pachelbel (1690頃) | FM ×3（`#OPM ON`・FM音色 @1/@2・`@v` 音量・2分→4分→8分変奏） |
    | `classic_twinkle_star.mml` | きらきら星 / フランス民謡（Mozart K.265） | FM + PSG + BEEP + Noise 全音源デモ（`#OPM ON`） |
  - **Local Files（ローカルフォルダ）**:
    - `OPEN LOCAL FOLDER...` ボタンによりローカルフォルダの選択・表示が可能（Chromium 系ブラウザでは File System Access API `showDirectoryPicker`、非対応環境では `<input webkitdirectory>` フォールバック）。
    - 読み込んだローカルフォルダのツリー構造と各ファイル内容は IndexedDB / localStorage に自動永続化され、ブラウザ再読み込み時にも完全復元される。
    - ツールバーより「新規MMLファイル作成 (`📄+`)」「新規フォルダ作成 (`📁+`)」を実行可能。
      - **新規ファイル作成時の挙動**: ディスク上に重複しないファイル名（`new_track.mml` / `new_track_N.mml`）で安全に初期作成され、エディタのタブに即座に自動オープン。ツリー上でインラインファイル名編集モード（テキストボックス）が自動でフォーカスされる。
      - **インラインリネーム (`✏️` / `F2` キー) & 実ディスク同期**: 
        - ファイルまたはフォルダを選択した状態で **`F2` キー** を押すか、ホバー時の鉛筆アイコン、または右クリックメニューから「名称変更」を選択してインライン編集を開始。
        - Enter（IME変換中は除外）またはフォーカスアウトで確定。File System Access API (`FileSystemHandle.prototype.move` または コピー&削除) を通じて実ディスク上のファイル名が即座に変更され、エクスプローラーツリーの表示名およびエディタのタブ名・アクティブファイル情報が自動的に同期・更新される。
      - **ファイル/フォルダ削除 (`🗑️` / `Delete` キー) & 実ディスク同期**: 
        - 選択状態で **`Delete` キー** を押すか、ゴミ箱アイコン、または右クリックメニューから削除確認ダイアログを表示。
        - 確認ダイアログでの承認後、実ディスクから対象エントリが削除され、エディタで該当ファイルが開かれていた場合はタブも連動して自動クローズされる。
      - **右クリックコンテキストメニュー (2026-09-08 新設)**:
        - ファイル上、フォルダ上、およびエクスプローラーの余白（背景）を右クリックすると、洗練されたダークテーマのコンテキストメニューが表示される。
        - **ファイル上**: 「名称変更 (`F2`)」「削除 (`Delete`)」「新規ファイル」「新規フォルダ」
        - **フォルダ上**: 「新規ファイル（該当フォルダ内）」「新規フォルダ（該当フォルダ内）」「名称変更 (`F2`)」「削除 (`Delete`)」
        - **背景余白**: 「新規ファイル（ルート）」「新規フォルダ（ルート）」
        - 画面端の見切れ自動補正、外側クリックまたは `Escape` キーでの自動クローズに対応。
    - フォルダ名横のクローズボタン（`<FolderX />`）でローカルフォルダをアンロードして初期状態（No Folder Opened）に復帰可能。
- **複数ファイル・タブ管理 (`MmlEditor.tsx`)**:

        - **ノイズ波形 @WN 選択 (2026-09-09 新設)**: @IN セレクタの右隣に配置。`AUTO (@WNn)` / `@WN0: 周期` / `@WN1: ホワイト` を選択。`AUTO` は MML キャレットの `@WN` 状態 (`noiseType`) へ追従し、MML キャレット移動時の自動連動で手動選択は `AUTO` へ戻る。NOISE エンジン選択時の発音 (`noiseType`) に反映され、周期ノイズは bandpass / ホワイトノイズは分周レート連動 lowpass で試聴できる。**有効化条件は実効音源が NOISE のときのみ**で、それ以外は `N/A (N1/N2)` の無効バッジ表示。
        - **FM VOICE選択 (2026-09-08 本実装)**: アクティブ MML 上で定義済みの FM 音色 (`@N`) を `@ID: NAME` 形式で動的リスト表示 (NAME 未設定時は `UNNAMED`、ID 昇順)。旧ハードコードのモック (`E.PIANO 1` / `SLAP BASS` 等の `DEFAULT_PRESET_FM_TONES`) は廃止。発音はプルダウンで選択中の定義音色で行い、TONE タブ表示中はエディタ編集中の音色を優先する。
        - **PITCH ENV / VOLUME ENV 選択 (2026-09-08 本実装)**: 同様にアクティブ MML 上で定義済みの `@PEN` / `@VEN` を `@PEID: NAME` / `@VEID: NAME` 形式で動的リスト表示 (NAME 未設定時は `UNNAMED`、ID 昇順)。旧ハードコードのモック (`Vib Mild` / `Piano Decay` 等の `PRESET_PITCH_ENVS` / `PRESET_VOL_ENVS`) は廃止。発音も選択中の MML 定義エンベロープのデータで行い、各 ENV エディタ表示中はエディタ編集中のカーブを優先する。
        - **VOLUME の DIRECT / @VE 手動選択の優先 (2026-09-08 修正)**: PSG / NOISE 時の `DIRECT` / `@VE` 切替は手動選択を最優先し、`DIRECT` 選択中は MML キャレットに `@VE` 指定があってもエンベロープを適用せず直接音量 (0〜15) で発音する。MML キャレット移動時の自動連動 (`@VE` 検出時に `@VE` モードへ自動切替) は従来どおり有効。

#### 2.1) Player との実データ連携 (Phase 5)
- **データ取得**: `App` が `Player`（演奏ファサード）を所有し、`getTrackLevel` / `getMasterLevel` の取得関数を props 経由で渡す。TrackMonitor は `Player` を直接参照しない（UI とロジックの疎結合）。
- **ポーリング**: 100ms 間隔の `setInterval` で VU を更新。停止中は同値チェック付きでメーターを沈静化（不要な再レンダリングを回避）。
- **プレビューミュート連携**: 各トラックのスピーカートグル / `ALL ON` / `MUTE` は `onTrackMuteChange` → `Player.setTrackVolume`（音量 0.8 固定、ミュートフラグのみ切替）に接続。**プレビュー専用パラメータであり MML コンパイル・エクスポートには影響しない**。
- **マスター音量**: スライダー / `MUTE` は `onMasterVolumeChange` → `App` state（一元管理）→ `Player.setMasterVolume` と `virtualSynth.setMasterVolume` の双方に接続（プレビュー専用）。

#### 3) マスターボリューム (プレビュー専用)
- ヘッダー右上に配置。
- **機能**:
  - スライダー (0%～100%)
  - 一括MUTEボタン (トグルで赤色発光)
  - Master L/R ミニステレオVUメーター (`Player.getMasterLevel` の実測値を表示)
- **仕様**: ブラウザ上のプレビュー試聴専用パラメータであり、**MMLコンパイル・エクスポート結果には一切影響しない**（UI上に `PREVIEW ONLY` / `(No effect on compile)` の注記を明示）。
- **影響範囲 (2026-09-09 拡張)**: 音量 / ミュート state は `App` で一元管理され、以下の **3 つのプレビュー経路のすべて**へ同一レベルが反映される:
  1. **演奏プレビュー (PLAY)**: `Player.setMasterVolume` — 知覚カーブ（2 乗曲線）を適用。
  2. **仮想キーボード発音 (鍵盤プレビュー)**: `virtualSynth.setMasterVolume` — 同一の知覚カーブ (`perceptualMasterGain`) を適用。スライダー変更は**発音中のノートへも即時反映**される。
  3. **右ペイン各エディタの試聴 (FM TONE / VOL ENV / PITCH ENV)**: `masterLevel` props (0-1、ミュート時 0) を各エディタへ渡し、基準出力ゲイン (FM: 0.35 / V-ENV: 0.25 / P-ENV: 0.2) に知覚カーブを乗算。スライダー変更は**発音中の試聴音へも即時反映**される。
- **値の保持**: マスター音量 / ミュートを `App` state で保持するため、TRACK MONITOR タブを離れて戻っても設定値はリセットされない。

#### 4) トラック一括操作
- カラムヘッダー（FM音源側、DCSG&BEEP側）にそれぞれ `ALL ON` / `MUTE` ボタンを備え、チップ系統ごとのソロ試聴・ミュートが可能。

#### 5) ワークトラック (Work Tracks: W1〜W99) 説明カード (2026-09-07 新設)
- **配置**: モニターパネル最下部に横長の Bento Card（`bg-[#242424] border border-[#3C3C3C]`）として配置。実機ハードウェアモニターのレイアウトを損なわず明快に掲示。
- **目的**: MIDI Import 時に実機チャンネルに収まらなかったトラックが `W1`〜`W99` として保存される仕組みと、MML TRANSFORM での再配分フローをユーザーに案内する。
- **仕様**:
  - **モニター機能は対象外**（`※モニター機能の対象外です（再生・VUメーター表示なし）` と明記）。実機ハードウェアには存在しない作業用素材のため、VUメーターやスピーカー制御は持たない。
  - **3つの要点をカード表示**:
    1. `素材の一時退避・保持`: MIDI Import 時にあふれたトラックや保留素材が MML 上に `W1`〜`W99` として欠落なく保存されること。
    2. `PSG (DCSG) 互換文法`: 文法は PSG 準拠（音程・オクターブ・音長・テンポ等）で記述でき、エディタ上で構文エラーにならず実機バイナリ生成（QDF/BIN）および演奏時は自動スキップされること。
    3. `MML TRANSFORM で実機へ配分`: 右上の `MML TRANSFORM` タブから作業用トラックを選んで `W# ➔ P#`（または `W# ➔ F#`）をクリックすることで、いつでも実機チャンネルへ簡単に一括再割り当てできること。

        - アスペクト比に依存しないピクセル距離計算（半径18px）により、ノードを確実にクリック可能。
        - Pointer Events（`setPointerCapture`）とドラッグ開始位置からの累積変位方式を採用。クロージャによる値固定や微小移動時のブルブル振動を根本解消し、マウス移動量に1対1で滑らかに数値・グラフ波形が追従。キャンバス外にマウスが外れても追跡を継続。
      - **操作方向に応じた動的マウスカーソル表現**:
        - `AR`（アタックレート）: 左右時間のみ変更可能 ➜ `ew-resize`（`↔`）
        - `D1`（ディケイ1変曲点）: 左右時間＋上下サステインレベル変更可能 ➜ `move`（全方位）
        - `D2`（ディケイ2終了点）: 上下減衰深度のみ変更可能 ➜ `ns-resize`（`↕`）
        - `RR`（リリースレート）: 左右時間のみ変更可能 ➜ `ew-resize`（`↔`）
      - ノードホバー/ドラッグ時のシアン発光＆拡大エフェクト、キャンバス下部のリアルタイムパラメータ解説ガイド付き。
  - **オペレータ選択 & 選択解除インタラクション**:
    - 通常クリック（Shift/Ctrlなし）時、未選択のOPをクリックするとそのOPのみを選択し他を解除。
    - すでに選択されているOPの `[SELECTED]` ボタンまたは余白をクリックした場合は**即座に選択解除（トグルオフ）**。
    - Shift / Ctrlキー押下時は、従来通り個別トグルによる複数選択に対応。
  - **複数選択時の直接数値入力（絶対値反映）と相対同期編集（ハイブリッド連動）**:
    - **直接数値入力 (Absolute Mode)**: 数値入力テキストボックスへキーボードで直接数値をタイピング入力した場合（またはセレクトボックスで選択した場合）、**入力した値そのものが選択中の全OPへ一括適用**され、指定の値へ瞬時に揃えることが可能。
    - **上下ボタン・ホイール・グラフドラッグ (Relative Mode)**: スピンボタン（`▲` / `▼`）、マウスホイール、Canvasエンベロープグラフのドラッグ、TLスライダーを操作した際は、他の選択中OPへ**操作元OPの変化差分（delta = newVal - oldVal）を相対的に加算・反映**。
    - 各パラメータの許容範囲（`TL: 0〜127`, `AR/D1R/D2R/RR: 0〜31`, `D1L/MUL: 0〜15`, `DT1: 0〜7`, `DT2: 0〜3`）で安全にクランプ。
    - 各OP固有のエンベロープ比率を活かした微調整と、同一値への一括リセット・統一入力の双方がシームレスに両立。

### 3.6 ピッチエンベロープエディタ (`PitchEnvelopeEditor.tsx`)
右ペインの第4タブ（`PITCH ENV`）に配置。主にDCSGやPSG、FM音源の1フレーム単位（1/60秒）のピッチオフセット（周波数変調・デチューン・ビブラート・ポルタメント）を直感的にグラフィカル編集するエディタ。Bento Grid DAWスタイルを適用。

- **Bento Card 構成**:
  - **Bento Card 1 (ヘッダー & トランスポート & プリセット)**:
    - タイトル、音源種別バッジ（`VIBRATO & BEND`）、ID 数値入力（`@PE0`〜`@PE255`）＋ MML定義状態バッジ（`DEFINED` / `UNDEFINED`、2026-09-06 新設）。
    - リアルタイム試聴トランスポート（`▶ TEST TONE` / `■ STOP`）。
    - トランスポート右横に `▶ MMLに反映` ボタン（エメラルド系）。**定義済み ID は MML の該当定義を置き換え、未定義 ID は最後の定義の後に新規挿入**する (2026-09-06 強化)。
    - ビブラート特化プリセット（ワンクリックロード）:
      - `VIBRATO (MILD)`: 自然で心地よい浅いビブラート（レンジ±7, 周期12F）。
      - `VIBRATO (DEEP)`: 深く揺れるダイナミックなビブラート（レンジ±15, 周期12F）。
      - `DELAYED VIB`: ストレート発音後にビブラート開始（12F以降ループ）。
      - `PITCH DROP`: 高音から急激に落ちるレーザー・効果音（レンジ±24）。
      - `PITCH UP`: 低音から素早く立ち上がるベンドアップ（レンジ±24）。
      - `FAST TRILL`: 高速で2音間を行き来するトリル（レンジ±7）。
    - ループ（`|`）の現在ステップ状態バッジ（ワンクリック解除ボタン付き。※ピッチエンベロープ `@PE` はリリースポイント `>` の仕様対象外）。
  - **Bento Card 2 (タイムライン & ダイナミックレンジ & 編集ツールバー)**:
    - **フレーム長可変（2〜128F）**: クイック長指定（`16F`, `32F*`, `64F`, `128F`）および `+` / `-` 微調整。
    - **用途に応じたダイナミックレンジ切替 (PITCH RANGE)**:
      - `±7` (Micro/Vib: 微小デチューン・浅いビブラート)
      - `±15` (Standard: 標準ビブラート・効果音)
      - `±24` (2 Octaves: 2オクターブ・ポルタメント)
      - `±48` (Wide Bend: ワイドピッチベンド・急降下/急上昇)
      - レンジ切替時も既存データを自動クランプしてシームレスに編集可能。
    - **プロDAW波形クイック編集ツール (TOOLS)**:
      - `GEN VIB ~`: 設定中レンジの約半分の振幅で周期8Fの正弦波ビブラートをタイムライン全体へ自動生成。
      - `INVERT ⇅`: ピッチ正負反転（`pitch * -1`）。
      - `FLIP ⇄`: タイムライン左右反転。
      - `SMOOTH`: 前後フレームの重み付き移動平均によるスムージング。
      - `CENTER 0`: 全ステップを 0（ピッチシフトなし）に一括リセット。
      - **波形・ピッチシフト (SHIFT)**:
        - `[→] 右シフト`: タイムラインを1ステップ右へシフト（先頭にStep 0の値を複製挿入）。
        - `[←] 左シフト`: タイムラインを1ステップ左へシフト（末尾に最終Stepの値を複製挿入）。
        - `[↑] 上シフト`: 全ステップのピッチを +1 加算（上限 +RANGE でクランプ）。
        - `[↓] 下シフト`: 全ステップのピッチを -1 減算（下限 -RANGE でクランプ）。
    - **タイムライン縦横同時ズーム & 水平スクロールパン**:
      - ズーム（`-`, `100%`, `+`, `Ctrl + マウスホイール` による60%〜350%拡縮）。
      - `SPACE: PAN` インジケータ兼先頭復帰ボタン（押下中は `✋ PANNING` 表示）。
      - `Space` キー押下ドラッグによる左右スクロール（パン）、ダブルクリックで先頭へスクロール。
    - **リアルタイムカーソル位置表示**: `POS: F[step] : P[pitch]`（正負符号付き）。
  - **Bento Card 3 (メイン・ピッチスタジオキャンバス)**:
    - **センターゼロ基準の双極性バーグラフ (Bipolar Bar Graph)**:
      - 中央の 0 レベルに白の破線基準ライン（センターライン）を配置。
      - プラス方向（ピッチ上昇）はQDシアン（`cyan-400`）の上向きバー。
      - マイナス方向（ピッチ下降）は温かみのあるアンバー（`amber-400`）の下向きバー。
      - 0レベル時はセンタードットで表示。
      - 再生中のステップにはシアンの縦ラインオーバーレイをリアルタイム追従描画。
    - **DAW風リージョン可視化**: ループ区間（`bg-cyan-500/[0.03]`）の透過帯と上部ブラケット。
    - **直接指定マーカーレーン**: `| LOOP` の自照式ボタントグル行。
    - **均等スロット & 線形補間（Interpolation）ドラッグ描画**:
      - 素早いペンドラッグでも虫食い抜けのない一筆書き描画。
      - **バー上マウスホイール連動**: バーグラフ領域でマウスホイールを上下スクロールすると、カーソル位置のステップのピッチが 1 ずつダイレクトに増減（-RANGE〜+RANGEクランプ）。Ctrl+ホイールのタイムラインズームとも安全に共存。
  - **Bento Card 4 (MML コマンド出力 & コピー)**:
    - `@PE1 = { |, 0, 3, 6, 8, ... }` 形式でリアルタイム生成、ワンクリッククリップボードコピー。
    - 同一生成ロジック（`generateMmlSnippet`）が `▶ MMLに反映` ボタンと共有されており、エディタヘッダーから直接MMLへの挿入も可能。
  - **Web Audio リアルタイム試聴**:
    - A4 (440Hz) ソートゥース波オシレーターを用い、1フレーム（約16.6ms）ごとに `pitch * 25 cents` のデチューン変調を適用。ビブラートやピッチベンドの聴感効果を忠実にシミュレート。

### 3.9 MML TRANSFORM パネル (`MmlTransformPanel.tsx` / 2026-09-07 新設・同日本実装完了)
右ペインの第6タブ（`MML TRANSFORM`）に配置（タブアイコン: `Wand2`）。MML 内の特定トラックや複数チャンネルに対して、**オクターブシフト・半音移調、およびチャンネルの一括再割り当て（リマップ）・スワップ** を直感的に一括適用するための専用スタジオ。適用は `src/core/transform/mmlTransformEngine.ts`（テキスト変換エンジン）経由で Monaco Editor に反映され、**Undo (Ctrl+Z) で変換前に戻せる**。

- **1. ヘッダー Bento Bar**:
  - タイトル: `MML TRANSFORM`、サブバッジ: `BATCH OPS`、音源状態バッジ: `17 CH (FM ON)` または `9 CH (MZ-1500 BASICS)`。
  - **SCOPE 選択**:
    - `Entire Track`（既定）: 対象トラックの全行に変換を適用。
    - `Selection`: エディタ上で反転選択している範囲のみに変換を適用（選択が無い場合は全文にフォールバックし、その旨をシステムコンソールへ記録）。
  - **適用トースト**: 変換適用時に `<操作内容> → [<対象トラック>] (<スコープ>)` の通知を緑色バッジで表示。
  - **MML 一括反映アクション (`APPLY TO MML` / 2026-09-07 強化)**:
    - ピッチ（オクターブシフト・半音移調）と音量スケーリングの双方を **1 回のトランザクションとして統合適用**（`handleApplyAll`）。
    - 変更が一切ない状態（オクターブ 0、半音 0、音量 100%/±0）またはトラック未選択時はボタンが disabled になり、無駄なエディタ書き換えを防止。
    - 選択中のチャンネル数および対象トラック名（例: `APPLY TO MML (4ch (W1,W2,W3,W4))`）を表示し、変換結果を MML へ直接書き戻す。

- **2. TARGET CHANNELS (対象トラック複数指定)**:
  - **クイック一括選択ボタン**:
    - `ALL (9ch / 17ch)`: 利用可能な全チャンネルを選択。
    - `DCSG (9ch)`: 本体標準音源（P1〜P6, N1〜N2, B1）を選択。
    - `FM (8ch)`: 拡張FM音源（F1〜F8）を選択（FM有効時のみ活性化）。
    - `WORK (4ch)`: 作業用プールトラック（W1〜W4）を選択。
    - `CLEAR`: 全選択解除。
  - **チャンネルボタングリッド (3グループ)**:
    - ① **MZ-1500 BASICS (9ch)**: `P1`〜`P6` (DCSG 矩形波), `N1`, `N2` (Noise), `B1` (BEEP)。水色アクティブ。
    - ② **YM2151 (ACZ-8BS1MZ / 8ch)**: `F1`〜`F8` (FM音源)。FM有効時は水色アクティブ、無効（OFF）時はグレーアウト・`DISABLED (OFF)` バッジおよび `+ 有効化する` リンクを表示。
    - ③ **WORK TRACKS (4ch)**: `W1`〜`W4` (作業用プール)。アンバー（琥珀色）基調で実機音源と視覚的に区別。

- **3. PITCH & VOLUME (ピッチ・オクターブ・音量の一括変換)** (2026-09-07 VOLUME SCALE 追加・動的表示強化):
  - **OCTAVE SHIFT**: `-2`, `-1`, `0`, `+1`, `+2`（オクターブ一括シフト）。
  - **TRANSPOSE (SEMITONE)**: `-12`〜`+12`（半音単位の移調）。
  - **VOLUME SCALE**: 加減算 `-2` / `-1` / `0` / `+1` / `+2` と割合 `50%` / `75%` / `100%` / `125%` / `150%` を選択し、`音量のみ反映` ボタンで一括適用。
  - **動的計算式プレビュー (2026-09-07 追加)**: 設定中の加減値と割合に応じた変換式（例: `※ 計算式: v = clamp(round(v × 75%) + 1) [DCSG: 0-15 / FM: 0-127]`、変更なし時は `※ 音量変更なし (100% / ±0)`）をリアルタイム表示。
  - `ピッチのみ反映` ボタンでオクターブ・移調のみを、`音量のみ反映` ボタンで音量スケーリングのみを個別適用可能。カードヘッダーの `RESET` でピッチ・音量の選択を一括リセット。

- **4. CHANNEL OPERATIONS (チャンネル再割り当て・スワップ)**:
  - タブ切替: `一括置換 (BATCH)` / `単体/スワップ`。
  - **注釈テキストの動的具体化 (2026-09-07 強化)**: 置換予定のペア（例: `P1➔P4, P2➔P5 など`）をリアルタイムに具体例として表示。
  - **PRESET MAPPINGS (クイックプリセット)**:
    - **`W# ➔ P# (実機へ)`**: 作業用トラック W1〜W4 を実機標準 DCSG (P1〜P4) へ一括展開。
    - **`W# ➔ F# (FMへ)`**: 作業用トラック W1〜W4 を実機拡張 FM (F1〜F4) へ一括展開（FM有効時のみ）。
    - `P# ➔ F# (FMへ)`: DCSG 矩形波チャンネルを FM 音源チャンネルへ同一番号移動（FM有効時のみ）。
    - `F# ➔ P# (DCSGへ)`: FM 音源チャンネルを DCSG 矩形波へ同一番号移動。
    - `P1-3 ➔ P4-6 (DCSG2へ)`: DCSG チップ1（P1〜P3, N1）からチップ2（P4〜P6, N2）へ移動。
  - **開始チャンネルから連番**: ドロップダウンで選択した開始チャンネル（例: `P1`）から、選択中トラックを順番に連番割り当て。
  - **個別マッピング対応リスト**: 選択中トラックごとの変換先ドロップダウン（`W1 ➔ P1`, `W2 ➔ P2` など）を並列表示し、個別に微調整可能。
  - **単一置換 & スワップ**: 単一の `A ➔ B` 置換、および `A ⇄ B` の安全な2チャンネル相互入替（スワップ）。

- **5. テキスト変換エンジン (`src/core/transform/` / 本実装)**:
  UI とロジックを疎結合にするため、変換ロジックは UI 非依存の純粋関数として `src/core/transform/` に実装する。適用フロー: パネルが `MmlTransformRequest`（説明文 + スコープ + `MmlTransformOperation[]`）を組み立て → `App.tsx` が Monaco Editor から対象テキストを取得して `applyMmlTransform` を順次適用 → `executeEdits` + `pushUndoStop` で書き戻し（Undo/Redo 履歴保持）→ 適用件数を SYSTEM CONSOLE へ `[MML TRANSFORM]` ログ出力。

  - **`mmlTrackScope.ts`（行スコープ解析）**: 各行のトラック帰属を解決する。検出ルールは正式パーサ (`MmlParser.detectTrackSpec`) 準拠: 行頭の大文字識別子のみ (`P1`-`P6` / `N1`-`N2` / `B1` / `F1`-`F8`)、カンマ区切り複数指定 (`F1,F2`) 可。作業用トラック (`W1`-`W99`) はパーサの W 行判定と同一条件（行頭 `W数字`）で検出。**継続行（宣言の無い行）は直前行のトラックに帰属**。マクロ定義行 (`@1 = { ... }` 等) とディレクティブ行 (`#TITLE` 等) は変換対象外（帰属は維持）。
  - **`mmlTransformEngine.ts`（変換操作）**: `applyMmlTransform(source, operation)` が単一の変換操作を適用し `{ source, changedCount }` を返す。操作種別:
    | 操作 | 内容 | クランプ |
    | :--- | :--- | :--- |
    | `remapTracks` | 行頭宣言の識別子を位置ベースで一括置換（スワップ等の衝突が起きない） | - |
    | `shiftOctave` | 対象トラックの `o` コマンド値を一括シフト（`<` / `>` は相対指定のため不変） | 0-10 |
    | `transpose` | 対象トラックの音符 (`a-g` + `+`/`#`/`-`) を半音移調。各トラックの現在オクターブを `o` / `<` / `>` で追跡（初期値 o4 = 正式パーサ `TrackState` と同一）し、**オクターブ跨ぎは音符直前に `o` コマンドを挿入**して表現。臨時記号は `#` 表記に正規化。連符 (`{ceg}`) 内は `o` 挿入不可のため現在オクターブの音域にクランプ | ノート 12-131 (o0c-o10b) |
    | `scaleVolume` | 対象トラックの音量を `round(v × percent/100) + add` で変換。`@v` (FM 音量) は行に FM トラック (`F1`-`F8`) が含まれる場合のみ適用 | `v` 0-15 / `@v` 0-127 |
  - **共通の保護仕様**: コメント (`;` / `/` 以降) は書き換えない。`t120` / `l8` / `v15` / `@1` 等のコマンド数値は音符と誤認しない。音長・付点・タイ (`^`)・休符 (`r`) は保持。実変化が無いトークンは `changedCount` に含めない（0 件時は「適用可能な変更はありませんでした」をログ出力し、エディタは更新しない）。
  - **テスト**: `src/core/transform/__tests__/mmlTransformEngine.test.ts` (30 件)。リマップ/スワップ/W トラック移動、オクターブシフトのクランプ、移調のオクターブ跨ぎ・継続行の状態引き継ぎ・連符内クランプ、音量スケーリングの FM/PSG 値域、加えて **変換後 MML が `MmlCompiler` でエラーゼロでコンパイルできること**（ノート番号の妥当性・SAMPLE MML 全曲への適用）を検証。

- **4. MIDI 解析 & MML 生成エンジン (`src/core/midi/` / 本実装)**:
  外部ライブラリ `@tonejs/midi` (SMF Format 0 / 1 対応) で解析した結果を UI 非依存の純粋関数で MML へ変換する。

  - **`midiToMmlConverter.ts` (変換エンジン)**:
    - `parseMidiFile(fileName, data)`: `Midi` (tonejs) で解析し、トラックごとの `MidiTrackSummary` (名前 / チャンネル / mono・poly 判定 / 最大同時発音数 / ノート数 / 音域 / ノート列) を返す。ノート時刻は `ticks / ppq` で**拍単位へ正規化** (テンポ変化の影響を受けない)。テンポ値は先頭イベントを採用し 30-255 にクランプ。ノートを含まないトラックは除外。
    - `extractVoice(notes, part)`: poly トラックを Top (最高音) / Middle (中央) / Bottom (最低音) の単音列へ分解。開始拍が重なるノートを同一グループ化して選択する。
    - `quantizeNoteLength(durationBeats)`: 発音長 (拍) を最も近い MML 音長 (1〜32 分 + 付点最大 2 個) へ量子化。
    - `convertNotesToMmlBody(notes)`: ノート列を 1 トラック分の MML ボディへ変換。開始拍は 32 分音符グリッドへスナップし、隙間は休符 (`r`) で埋め、オクターブ変更時のみ `o` コマンドを出力。音名はシャープ表記 (`midiNoteToMmlName`)。ノート番号は MML 表現可能範囲 (o0c-o10b = 12-131) にクランプ。
    - `autoAssignRouting(tracks, enableFm, fmFirst)`: ドラム (ch10) → `N1`/`N2`、最初の poly → `SPLIT(3)`、mono → `P1`/`P5`/`P6` (P2-P4 はスプリット用に予約) → FM → `W1`-`W4` → `Unassigned`。`fmFirst` (fm_full プリセット) では FM を優先。
    - `generateMml(meta, parts)`: `AssignedPart` (出力先トラック + ボイス分解済みノート列 + 代表音量) のリストから MML を生成。実機トラックを先に、W トラックを後にグループ化。テンポ (`t`) は最初の実機トラック行のみ。トラック行書式: `P1  t120 v12 q7 l16 <body>  ; from <元トラック名>`。ベロシティ (0-1) は `v1`-`v15` へ変換。
  - **`demoMidi.ts` (内蔵デモ MIDI)**: SMF Format 1 のバイト列をコードで構築するヘルパ。`Load Demo File` ボタンと単体テストフィクスチャで共用 (Melody mono / Chords poly 3 和音 / Drums ch10 の 4 トラック構成)。
  - **モーダル側のデータフロー** (`MidiRouterModal.tsx`): ドロップ / ファイル選択 → `file.arrayBuffer()` → `parseMidiFile` → `autoAssignRouting` でトラックリスト構築 → ミュート / ソロ / SPLIT ターゲット設定 → `✔ APPLY TO MML` で `generateMml` を実行し `onApplyToMml` へ。プリセット変更 (`standard` / `fm_full`) は実データへの再ルーティングとして動作する。`Reset` ボタンは現在のファイルに対するルーティングやり直し。
  - **テスト**: `src/core/midi/__tests__/midiToMmlConverter.test.ts` (19 件)。デモ MIDI の解析 (BPM・mono/poly・パーカッション判定)、ボイス抽出、音長量子化、MML ボディ変換 (休符・オクターブ・オフグリッドスナップ)、出力構成 (実機→W 順・テンポ 1 回)、自動ルーティング、および **生成 MML の `MmlCompiler` エラーゼロ検証**。

- **5. トラックテスト再生 (GM SoundFont / `midiPreview.ts` / 2026-09-07 追加)**:
  Column 1 の各 MIDI トラック行の `Preview Track` ボタン (▶ / ■ トグル) で、そのトラックのノート列を **smplr の General MIDI SoundFont** で試聴再生する。さらに Column 1 ヘッダーの `PREVIEW ALL` ボタンで**全パートの同時試聴**が可能。

  - **音源**: `acoustic_grand_piano` (旋律トラック) / `synth_drum` (パーカッション ch10 トラック)。SoundFont データはネットワーク (CDN) から取得しブラウザ Cache API でキャッシュ。**取得に失敗した場合 (オフライン等) はモーダルヘッダー下に赤色エラーバッジを表示**し、再生状態を解除する。
  - **再生方式**: `buildPreviewSchedule` でノート列 (拍単位) を秒単位のスケジュールへ変換 (BPM 30-255 クランプ / ノート番号 12-131 クランプ / ベロシティ 0-1 → 1-127) し、AudioContext 時間基準でプリスケジューリング。トラック末尾まで再生すると自動で再生状態が解除 (ループなし)。再生中に同じボタンで即停止。
  - **全パート試聴 (`PREVIEW ALL`)**: Column 1 ヘッダーのボタンで全トラックを同時再生。旋律 / パーカッションを `buildMultiPartSchedule` で 2 系統に分離してそれぞれの GM 楽器で鳴らす。**ミュート / ソロの状態を反映** (ソロ有効時はソロトラックのみ)。
  - **確実な停止**: smplr の `stop()` は発音中の voice しか止めないため、`start()` の戻り値 (スケジュールキャンセル + voice 停止) を全ノート分保持し、`stop()` 時に一括呼び出しする。さらに世代カウンタにより、SoundFont ロード待ち (`await`) 中に停止された古い再生要求を無効化する。
  - **停止タイミング**: 再ルーティング / プリセット変更 / `Clear` / モーダルを閉じる (`X` / `Close` / `APPLY TO MML`) のいずれでも停止。モーダルの閉鎖は `handleClose` 経由で統一。
  - **テスト**: `src/core/midi/__tests__/midiPreview.test.ts` (10 件)。スケジュール生成 (`buildPreviewSchedule` / `buildMultiPartSchedule`) の純粋関数を検証 (BPM / ノート番号クランプ、ソート、ベロシティ変換、最小音長、旋律 / パーカッション分離、総時間)。AudioContext 依存の再生部分は実機 (ブラウザ) でのみ確認可能。

### 3.11 ワークトラック仕様 (Work Track System: `W1`〜`W99` / 2026-09-07 新設)
MIDI Import から MML 編集、そして MML TRANSFORM への**一貫した編曲パイプライン**を実現するための作業用トラック概念。

1. **基本方針**:
   - トラック識別子: `W1` 〜 `W99`（Work Track）。
   - 文法仕様: **PSG (DCSG) 互換**（音程 `c-b`、オクターブ `o1-o8`、音長 `l`、テンポ `t`、音量 `v0-v15` 等）。
   - Monaco Editor / シンタックスハイライト: PSG トラックと同等の構文認識を行い、エディタ上で `PROBLEMS: 0`（エラーなし）を維持。

2. **コンパイラ・実機演奏・エクスポート時の扱い**:
   - `MmlParser`: 行頭が `W1`〜`W99` で始まる行は、実機音源バイナリ生成対象外として**安全にスキップ**。
   - 実機Z80ドライバーによる演奏時、および実機QDイメージ（`.qdf`）やバイナリ生成時には自動的に除外されるため、実機ハードウェアには一切影響しない。
   - トラックモニター機能の対象外（再生音・VUメーターなし）。

3. **制作・編曲ワークフロー**:
   - **MIDI Import 時**: 多数のトラックや分厚い和音を含む MIDI を取り込んだ際、実機（9ch または 17ch）に収まらなかったパートを自動的に `W1`〜`W99` に退避・保存（データの欠落ゼロ）。
   - **MML TRANSFORM 時**: 保留された `W1`〜`W99` をパレット素材として扱い、`W# ➔ P#` や `W# ➔ F#` のプリセットを用いて、後から好みの実機チャンネルへ段階的に展開・割り当て可能。

   - ボタンラベル: `OPEN LOCAL FOLDER...`（アイコン: `<FolderOpen />`）。
   - ホバーツールチップ: 「PCのローカルフォルダを選択してMMLプロジェクトを開く」。

2. **ブラウザネイティブのフォルダ読み込みアーキテクチャ**:
   - **Primary (Chromium系)**: File System Access API (`window.showDirectoryPicker()`) を優先使用。
     - ユーザーが選択をキャンセル（`AbortError`）した場合は安全にハンドリング。
     - ディレクトリハンドルから再帰的に子ディレクトリおよびファイルを走査（`scanDirectoryPicker`）。
   - **Fallback (Safari/Firefox等)**: 隠し `<input type="file" webkitdirectory directory multiple />` をクリック発火。
     - `file.webkitRelativePath` から階層ツリーをメモリ上に自動構築（`buildFileTreeFromFiles`）。
   - **ソートルール**: 各階層でフォルダが先行、同一種別は名前順（アルファベット順）に整列。

3. **初期空状態 & モック撤廃**:
   - 初期起動時およびフォルダ未ロード時はモック（`my_game_bgm`）を表示せず、クリーンな空状態（`No Folder Opened`）を表示。
   - `Local Files` 見出し横に `EMPTY` バッジを掲示し、中央に点線カードで「OPEN LOCAL FOLDER...」を促すガイダンスを表示。

4. **IndexedDB / localStorage による自動永続化 & 次回起動時復元**:
   - 一度読み込んだローカルフォルダのツリー構造とMML等のテキストファイル内容（`content`）は、ブラウザの IndexedDB（フォールバック時は localStorage）へ自動保存（`workspaceStorage.ts`）。
   - 次回ブラウザを開いた際やリロード時にも前回のフォルダツリーが即座に自動復元され、実ファイル選択なしにそのまま作業を継続可能。
   - ファイルツリー上で新規ファイル作成、新規フォルダ作成、リネーム、削除を行った場合も自動的にストレージと同期。

5. **ワークスペース状態・自動読み込み連動**:
   - フォルダ読み込み完了後、フォルダ名を `Local Files (<フォルダ名>)` として表示し、バッジを `WORKSPACE` に更新。
   - プロジェクト内に `.mml` ファイルが存在する場合、先頭の `.mml` ファイルを自動的にエディタタブへ自動展開（`onSelectFile`）。
   - ツリー上のファイル項目をクリックした際、セッション中であれば実ファイルから最新内容を取得、リロード後の復元データであれば保持している `content` をエディタへ展開。

6. **フォルダを閉じる（Close / Unload Folder）**:
   - フォルダが開いている際、`WORKSPACE` バッジ横に「フォルダを閉じる」ボタン（`<FolderX />`）を表示。
   - クリックするとストレージ内のワークスペース情報がクリアされ、初期の空状態へ安全に戻すことが可能。

7. **ファイル・フォルダのリネーム・実ディスク同期 & コンテキストメニュー (2026-09-08)**:
   - **F2 キー / コンテキストメニューからのリネーム**:
     - 項目選択中に `F2` キー押下、または右クリックメニューの「名称変更 (F2)」でインライン入力欄が即座にアクティブ化。
     - IME確定の `Enter` ではコミットせず、変換確定後の `Enter` またはフォーカスアウト（Blur）でコミット。空文字・変更なし時は安全にキャンセル。
   - **実ディスクへの即時反映**:
     - File System Access API の `move()` または作成&削除によるリネームを実行し、`rescanLocalFolder()` で実ファイル構造と再同期。
   - **エディタタブとの連動**:
     - 開いているエディタタブの `fileName`・`filePath` およびアクティブファイルIDを追従更新。
   - **右クリックコンテキストメニュー**:
     - ファイル上: 「名称変更 (F2)」「削除 (Del)」
     - フォルダ上: 「新規ファイル」「新規フォルダ」「名称変更 (F2)」「削除 (Del)」
     - 空白背景上: 「新規ファイル」「新規フォルダ」
     - `createPortal(..., document.body)` により、ペイン境界を跨ぐ位置でも最前面（`z-[9999]`）に描画され見切れや重なりを防止。

8. **確認ダイアログの全面モーダル表示 (`ConfirmDialog.tsx` / 2026-09-08)**:
   - 削除確認や保存確認ダイアログは、親コンテナ（Left Pane の `z-0` 等）のスタッキングコンテキストに閉じ込められないよう、React Portal (`createPortal(..., document.body)`) を採用。
   - ウィンドウ全体の中央・最前面（`z-[9999]`）に暗色オーバーレイとともに描画され、TONEやV-ENV等の右ペインの裏に隠れることなく確実に全面表示される。

9. **「エクスプローラーで表示」(Reveal in File Explorer) の技術的制約と見送り判断 (2026-09-08 確定)**:
   - **結論**: VS Code の「エクスプローラーで表示」相当機能（エクスプローラー右クリックから OS ネイティブのファイルエクスプローラー / Finder で該当フォルダ・ファイルを表示）は、**Web ブラウザアプリである本 IDE では技術的に実現不可のため実装を見送り** (2026-09-08 ユーザー確定)。
   - **制約の技術的理由**:
     - VS Code は Electron デスクトップアプリであり、Node.js / `shell.showItemInFolder()` による OS ネイティブ呼び出しが可能。一方本 IDE はブラウザのセキュリティサンドボックス内で動作し、Web 標準 API には OS のウィンドウを開く・表示する手段が存在しない。
     - W3C File System Access API にも、保持している `FileSystemDirectoryHandle` / `FileSystemFileHandle` から OS ネイティブのエクスプローラーを起動する API、および OS 絶対パスを取得する API は非公開 (セキュリティ上の理由)。
     - `window.open('file:///...')` 等による file スキーム起動はブラウザセキュリティポリシーによりブロックされる。
     - 本プロジェクトの技術方針「**Web ネイティブ完結 (C# / .NET WebAssembly / Electron 不使用)**」を維持するため、Electron 化による実現も行わない。
   - **代替案の検討結果 (不採用)**:
     - `showDirectoryPicker({ startIn: dirHandle })` で該当場所を起点にフォルダ選択ダイアログを開く方式は技術的に可能だが、「ダイアログ表示中はページ操作がブロックされる」「純粋なエクスプローラー表示ではない」ため不採用とした。
   - **将来再検討のトリガー**: Electron / Tauri 等デスクトップアプリ化の方針転換が行われた場合に限り再検討可能。

### 3.14 音色 & エンベロープ名称仕様 (`/* NAME: 音色名 */` / 2026-09-07)
FM TONE（`@N`）、V-ENV（`@VEN`）、P-ENV（`@PEN`）において、ユーザーが任意の名称を設定・記憶・復元できる仕様。

1. **コメント構文ルール (パターン1 タグ形式 + 後方互換フォールバック)**:
   - **標準出力書式**: `/* NAME: 音色名 */`（大文字 `NAME:` または小文字 `name:`）
   - **例** (FM TONE 定義は 2026-09-08 確定の新出力書式):
     ```mml
     @1 = {
       /* NAME: E.PIANO 1 */
       /* ALG, FB */
       4, 6,
       /* AR, D1R, D2R, RR, D1L, TL, KS, MUL, DT1, DT2, AME */
       31, 12, 4, 10, 3, 45, 1, 1, 0, 0, 0,
       31, 18, 2, 8, 6, 24, 1, 1, 3, 0, 0,
       31, 14, 3, 9, 4, 32, 2, 14, 0, 0, 0,
       31, 8, 1, 7, 2, 0, 1, 1, 0, 0, 0
     }
     @VE2 = {
       /* NAME: Pluck Fast */
       15, 12, 9, 6, 3, 0
     }
     @PE1 = {
       /* NAME: Slow Vibrato */
       | 0, 1, 2, 1, 0, -1, -2, -1
     }
     ```
   - **後方互換性**: `NAME:` タグがない場合でも、パラメータメタ情報（`ALG`, `OP1`, `FB`, `AR` 等のラベルコメント）を含まない最初のコメントを自動的に名前として解釈（従来の `/* E.PIANO 1 */` 等もそのまま復元可能）。

2. **各エディタヘッダーの「NAME」入力欄**:
   - **FM TONE (`FmToneEditor`)**: ヘッダーの `@ID` 右隣に `NAME:` 入力欄（テキストボックス）を新設。
   - **V-ENV (`VolEnvelopeEditor`)**: ヘッダーの `@VE` 右隣に `NAME:` 入力欄を新設。
   - **P-ENV (`PitchEnvelopeEditor`)**: ヘッダーの `@PE` 右隣に `NAME:` 入力欄を新設。
   - **プリセット選択時は NAME には何も設定しない** (2026-09-08 変更): プリセットはあくまでパラメータの参考値としてのみ使用し、既存の NAME 入力値はそのまま保持される。名称の復元は MML からのロード時（`/* NAME: ... */` コメント）のみ行われる。
   - **NAME 未設定時の統一書式 (2026-09-08)**: 3 エディタとも NAME 入力欄の初期値・未設定値は**空文字**で統一 (FM TONE の初期プリセット音色名も設定しない)。未設定のまま「▶ MMLに反映」した場合は `/* NAME: UNNAMED */` へフォールバックされ、FM TONE / V-ENV / P-ENV 間で表記が統一される (旧 V-ENV / P-ENV の `DEFAULT` 表記は廃止)。

3. **双方向連動**:
   - 「▶ MMLに反映」ボタン押下時、入力された名称が `/* NAME: ... */` コメントとして MML 内に出力される。
   - MML からのロード時（ID 変更や MML クリック時）も、定義コメントから自動的に名称が抽出されエディタの入力欄に復元される。

4. **FM TONE 定義の MML 出力書式 (2026-09-08 簡素化)**:
   - 「▶ MMLに反映」の出力 (`FmToneEditor.generateMmlSnippet`) は、コメントラベルを `/* NAME: ... */`・`/* ALG, FB */` (数値なし)・`/* AR, D1R, D2R, RR, D1L, TL, KS, MUL, DT1, DT2, AME */` (OP1〜OP4 共通のパラメータ順説明、1 回のみ) に簡素化。
   - **OP 個別のラベル (`/* OP1: ... */` 〜 `/* OP4 (Carrier) */`) と行末の `; Carrier` 表記は付与しない** (2026-09-08 ユーザー確定)。
   - 従来書式 (`/* ALG=4, FB=6 */` 数値入りラベル・OP 個別ラベル) を含む既存 MML も、コンパイル (`MmlCompilerMacros.splitMacroTokens`) とロード (`mmlDefinitionLoader.splitDefinitionTokens`) の両方でコメント除去後に数値列をパースするため後方互換で解釈可能。
