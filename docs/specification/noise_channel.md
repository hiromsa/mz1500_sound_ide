# DCSG ノイズチャンネル仕様 (SN76489AN / N1・N2)

MZ-1500 Sound IDE のノイズトラック (N1 / N2) に関する**ハードウェア・MML・ドライバ実装を貫く総合仕様**。
MML コマンドの詳細な文法は [mml_reference.md](./mml_reference.md) §3.6 を参照。本書はノイズに特化して原理から説明する。

---

## 1. 早見表 (やりたいこと逆引き)

| やりたいこと | MML の書き方 | 実際の音 |
|---|---|---|
| ドラム・スネア (定番の「シャー」) | `N1 @WN1` (+ `v` `l` `q`) | 固定クロックのホワイトノイズ (高さは変わらない) |
| 高い金属音 (ハイハット代わり) | `N1 @WN0` | 約 3.5kHz 固定の「キーン」(高さは変わらない) |
| **音程に合わせて高さが変わる金属音** | `N1 @IN1 @WN0 o4 c e g` | 音符の音程がそのまま基本波になる金属音 |
| 音程に合わせて帯域が変わる白噪 | `N1 @IN2 @WN1 o4 c e g` | 音程 × 16 のクロックで散る白噪 |
| 連動をオフに戻す | `N1 @IN0` | 以後は固定クロック (hint) に戻る |

**最重要**: `@WN` 単体では**高さは一切変わらない** (SN76489 のハードウェア制約)。音程追従には必ず `@IN1` / `@IN2` を併用する。

## 2. ハードウェア構成

### 2.1 MZ-1500 の音源構成とトラック割り当て

MZ-1500 は SN76489AN (DCSG) を 2 個搭載:

| デバイス | I/O ポート | 出力 | トラック割り当て (MZSD trackIndex) |
|---|---|---|---|
| PSG1 | 0xF2 | 左チャンネル | P1 (0), P2 (1), P3 (2), **N1 (3)** |
| PSG2 | 0xF3 | 右チャンネル | P4 (4), P5 (5), P6 (6), **N2 (7)** |

各 PSG は「矩形波 3ch + ノイズ 1ch」で構成され、**ノイズチャンネルは各 PSG の 4 番目 (ch3)**。
クロックは 3,579,545 Hz。

### 2.2 ノイズ生成回路 (LFSR)

SN76489AN のノイズは 16bit シフトレジスタ (LFSR) で生成:

- **ホワイトノイズ**: フィードバック = `bit0 XOR bit3` → 最大長系列 (周期 65535 ステップ)。「シャー」という広帯域ノイズ
- **周期ノイズ (Periodic)**: フィードバック = `bit0` (1 ビット循環) → **16 ステップ周期**の短い循環。シフトクロックを f とすると f/16 の「キーン」という金属音

出力は LFSR の bit0 (±1 の矩形)。

### 2.3 ノイズシフトクロック (rate)

LFSR を 1 ステップ進めるクロックはノイズ制御レジスタの下位 2bit (rate) で選ぶ:

| rate | シフトクロック | periodic の音の高さ |
|---|---|---|
| 0 | Clock/16 = 223.7 kHz | 約 14.0 kHz |
| 1 | Clock/32 = 111.9 kHz | 約 7.0 kHz |
| 2 | Clock/64 = 55.9 kHz | **約 3.5 kHz** (最も低い) |
| 3 | **tone2 周波数 × 16** (連動) | **音符の音程** と等しくなる |

- rate 0〜2 は「固定クロック」= 音程とは無関係
- **rate 3 が「3ch (P3/P6) との同期」**: 同一 PSG 内の tone2 (P3 または P6 の音程レジスタ) の出力で LFSR が駆動される。tone2 が音程 f で鳴っていれば LFSR は f × 16 でシフト → periodic の基本波 = f、white の散らばりも f に比例

### 2.4 SN76489 レジスタ (データポート 0xF2 / 0xF3 への書き込み)

| バイト値 | 意味 |
|---|---|
| `0xE0 \| (white << 2) \| rate` | ノイズ制御 (white: 0=periodic / 1=white、rate: 0-3) |
| `0xF0 \| att` | ノイズ減衰 (att = 15 - v、0=最大音量 / 15=無音、2dB/step) |
| `0x80 \| (2 << 5) \| (period & 0x0F)` | tone2 period 下位 (fine ラッチ) — 同期時の音程書き込み |
| `(period >> 4) & 0x3F` (bit7=0) | tone2 period 上位 (coarse データ) |

## 3. MML コマンドと内部フラグ

`@WN` と `@IN` は **独立したビット** を持ち、**どちらを先に書いても組み合わせが保持**される (片方を書き換えても他方はリセットされない)。

| コマンド | 機能 | NOISECTL flags への反映 |
|---|---|---|
| `@WN0` | 周期ノイズ (金属音) | bit0 = 0 |
| `@WN1` | ホワイトノイズ | bit0 = 1 |
| `@IN0` | 連動オフ (固定クロック) | bit1-2 = 0 |
| `@IN1` | 連動 ON | bit1-2 = 1 |
| `@IN2` | 連動 ON | bit1-2 = 2 |

```
flags: bit0 = white (波形)   ← @WN が管理
       bit1-2 = sync (連動)  ← @IN が管理
```

### 3.1 実装上の重要事項

1. **`@IN1` と `@IN2` の実装上の違いは sync ビット値 (1 / 2) のみで、演奏挙動は同一** (どちらも rate 3 = tone2 連動になる)。波形は `@WN` 側で決める。
   - 慣例として「`@IN1` + `@WN0` = 連動周期」「`@IN2` + `@WN1` = 連動白噪」の組み合わせで使う
   - `@IN2` 単独では波形は変わらない (`@WN` が最後に指定した方のまま)
2. **`@IN` は N1 / N2 に書く**。P3 / P6 に書くと警告「@in はノイズ トラック (N1, N2) でのみ有効です」が出てコード出力されない (P3/P6 は「同期源として機能するチャンネル」の意味で、コマンドの記述先ではない)
3. ノイズトラックで有効な他のコマンド: `v` (0-15)、`@VE` (音量エンベロープ)、`q`/`@q` (ゲート)、`o`/`<>`/`K` (音程 = 同期時の高さ)、`t`/`l`、`[ ]`/`L`
4. **ノイズトラックで無効なコマンド**: `@SW` / `@PE` / `D` (ピッチ系 = トーンの period を動かす効果。ノイズトラックの NOTE は tone2 を 1 回書くだけで、これらのフレーム進行は適用されない)

### 3.2 連動時の音程指定

`@IN1` / `@IN2` 中、**N1 (N2) の音符の音程が tone2 (P3/P6 相当のレジスタ) へ書き込まれる**。
N1 単独でも音程追従が成立する (P3 に音符を書く必要はない)。

**P3 (P6) との併用注意**: 同一 PSG の tone2 は 1 本しかない。
`@IN` 中に N1 と P3 が**同時に**音符を鳴らすと、両者が交互に tone2 を上書きし合う (最後に書いた方が勝つ)。安全な運用は:

- N1 のみで音程を書き、P3 は使わない (または休符)
- P3 と N1 に**同じ音程列**を書く (ユニゾン = 上書きが同値なので干渉しない)

### 3.3 非連動時の分周ヒント (rate 0-2 の自動選択)

`@IN` なし (連動オフ) のとき、ドライバは**音符の高さから rate を 3 段階で自動選択**する:

| 実装 | 判定 | 実用音域 (o1〜o10 ≈ 33Hz〜16.7kHz) での選択 |
|---|---|---|
| SourceInterpreter (`TrackSequencer`) | 音符周波数 < 40kHz → rate 2 / < 80kHz → rate 1 / else rate 0 | **常に rate 2 (55.9kHz)** |
| 実機ドライバ (`mzsd_driver.asm`) | tone period == 0 → 0 / == 1 → 1 / else 2 | **常に rate 2** |

つまり実用音域では rate 2 に丸められ、`@WN0` は約 3.5kHz 固定、`@WN1` はいつも同じ帯域の「シャー」になる。**これは実機 (.qdf) でも同じ挙動**。

> **注意**: C# 版オリジナルのリファレンス (`mz1500_sound_driver/mml_reference.md` §5.1) には
> 「音符 c〜d で Low / e〜f で Mid / g 以上で High が切り替わる」との記述があるが、
> C# 実装 (`TrackSequencer.cs` の `freq < 40000 ? 2 : freq < 80000 ? 1 : 0`) とは一致しない
> (実用音域では常に rate 2)。本 IDE は C# **実装**に準拠する。

### 3.4 C# オリジナルとの整合

本仕様 (§3) は C# 版オリジナルと**ビットレベルで同一**である (裏付け):

| 項目 | C# 版 (`MzSound.MmlCompiler` / `MzSound.Player`) | 本 IDE (TS) |
|---|---|---|
| `@WN` の反映 | `NoiseFlags = (NoiseFlags & ~0x01) \| mode` (bit0 のみ) | 同一 (`MmlParser.processNoiseWave`) |
| `@IN` の反映 | `NoiseFlags = (NoiseFlags & ~0x06) \| (mode << 1)` (bit1-2 のみ) | 同一 (`MmlParser.processNoiseSync`) |
| N1/N2 以外への記述 | 警告「@wn / @in はノイズ トラック (N1, N2) でのみ有効です」 | 同一文言の警告 |
| 同期の判定 | `(_noiseFlags >> 1) & 0x3 != 0` → rate 3 | 同一 |
| 非連動時の hint | `freq < 40000 ? 2 : freq < 80000 ? 1 : 0` | 同一 |

**`@IN` を P3 / P6 に書く仕様は存在しない** (C# 版も警告になる)。「P3/P6 と連動する機能」を `@IN` が提供するため、混同しやすい。
同期ノイズのノウハウ (C# 版 `mz1500_sound_driver/mml_reference.md` §5 より):
- 連動白噪 (`@IN2 @WN1`) で **o10 など極端に高い音程**を指定すると、音程 × 16 の超高速シフトになり「絹のように細かい」白噪になる (音符としての音程感はほぼ消える)
- ピッチエンベロープ (@EP) をノイズトラックに併用して「急降下スネア」を作る手法は C# 版リファレンスに記載があるが、**現行実装 (C# / TS とも) ではノイズトラックに @EP は適用されない**ため動作しない (将来拡張の検討事項)

## 4. MZSD ドライバ実装

### 4.1 NOISECTL 命令 (0x0A)

MML の `@WN` / `@IN` は各ノイズトラックのデータ列へ `NOISECTL (0x0A) + flags (1byte)` として出力される。
flags は §3 のビット構成。複数回書けばその都度レジスタへ即時反映される。

### 4.2 処理フロー (両エンジン共通の概念)

```
MML "@WN1" ──┐
MML "@IN1" ──┴─> MmlParser ──> NOISECTL flags ──> ドライバ
                                                    │
音符 NOTE ────────────────────────────────────────> ├─ hint 計算 (非連動時の rate)
                                                    ├─ 同期時: tone2 へ period 書き込み
                                                    ├─ apply_noise: 0xE0|white<<2|rate 出力
                                                    └─ write_att: 0xF0|att 出力
```

### 4.3 SourceInterpreter (`src/core/player/TrackSequencer.ts`)

- `NoiseCtl` 命令: `noiseFlags` を保存し `applyNoiseMode()` で即時 `setNoiseControl(white, sync ? 3 : hint)` を呼ぶ
- `startNote` (ノイズ): `hint = freq < 40000 ? 2 : freq < 80000 ? 1 : 0` を更新 → `applyNoiseMode()` → **sync != 0 なら `setTonePeriod(2, periodFor(freq))`** (同一 PSG の tone2 へ)

### 4.4 実機ドライバ (`driver/mzsd_driver.asm`)

- `ev_noisectl`: `CH_NOISE` ワークへ flags を保存し `apply_noise` を即時呼ぶ
- `play_noise` (NOTE 処理): `note_dctbl` から period を取得 → hint 計算 (`p==0→0 / p==1→1 / else→2`) → **sync (`CH_NOISE & 0x06`) 非 0 なら tone2 の fine (`0xC0|period&0x0F`) / coarse (`(period>>4)&0x3F`) を PSG ポートへ出力** → `apply_noise` (`0xE0|white<<2|rate`) → `write_att` (`0x90|(3<<5)|att` = `0xF0|att`)
- 両エンジンの等価性は `Z80DriverEquivalence.test.ts` (全フレーム音源レジスタ比較) で検証済み

## 5. Web エミュレーション (DcsgChip) の固有実装

`src/core/chips/DcsgChip.ts` のノイズ関連は以下のとおり (C# オリジナルからの意図的差分を含む — 詳細は [web_core_port.md](./web_core_port.md) §3.1):

1. **LFSR は 16bit** (`bit15` 挿入、初期値 0x8000)。white = `bit0 XOR bit3`。
   - C# 版は AND フィードバックのため白噪が即無音化するバグ、および 15bit 化すると 63 ステップの短循環 (約 890Hz のブザー音) になる問題を修正した差分実装
2. **ノイズ出力に 2 段 1-pole LPF (8kHz) + RMS 補正 + DC ブロック (30Hz)** を実装。
   - シフトクロック (55.9〜223.7kHz) が音声ナイキスト (24kHz) を超えることで生じる標本化エイリアス (金属的な高音) を、実機のアナログ出力段相当に減衰する
3. 仮想キーボード (`src/utils/virtualSynth.ts`) のノイズは Web Audio 直結の別実装 (白噪 lowpass 8kHz / 周期ノイズは音符周波数中心の bandpass)。演奏経路 (PLAY) と音質基準を揃えてある

## 6. MML 記述例

```mml
; --- ドラム (定番): 高さ不要の白噪 ---
N1 @WN1 v12 l8 c c c c r

; --- 音程追従の金属音 (メロディック) ---
N1 @IN1 @WN0 v10 l4 o5 c d e f
N1 @IN1 @WN0 v10 l4 g f e d      ; flags は保持される (@IN1 の再記述は不要)

; --- 音程追従の白噪 (帯域が音程で変わる) ---
N1 @IN2 @WN1 v10 l8 o4 cc ee gg

; --- 連動オフに戻す ---
N1 @IN0 @WN1 v12 l8 cccc

; --- ハイハット風: 小音量の周期ノイズ + 短いゲート ---
N1 @WN0 v6 q2 l16 cccc cccc
```

実サンプル:
- `samples/mml_reference/psg/psg_noise_basic.mml` — @WN / @IN / v の基本
- `samples/mml_reference/psg/psg_noise_interlock.mml` — @IN 連動の応用

## 7. FAQ (よくある落とし穴)

### Q1. `@WN0` を o4 c e g と書いても高さが変わらない

**仕様どおり**。非連動ノイズのクロックは固定分周 3 段階しかなく、実用音域では常に最も低い rate 2 (periodic ≈ 3.5kHz) に丸められる。実機でも同じ。音程追従は `@IN1` を併用する (§1, §3.3)。

### Q2. `@IN1` を書いたのに「シャー」のまま / `@IN2` で音色が変わらない

`@IN1` / `@IN2` は**連動 (rate 3) の ON** のみで、**波形 (white/periodic) は `@WN` で指定**する。`@IN1` + `@WN1` は「連動白噪」、`@IN2` + `@WN0` は「連動周期ノイズ」になる (実装上どちらの連動も同じ)。

### Q3. P3 と N1 を同時に鳴らすと音程がおかしくなる

`@IN` 中は N1 の音符が PSG1 の tone2 (P3 の音程レジスタ) を書くため、P3 の旋律と衝突する (§3.2)。N1 だけで音程を書くか、P3 とユニゾンさせる。

### Q4. ノイズの音量が変わらない / 変えたい

`v0`〜`v15` (15=最大)。`@VE` (音量エンベロープ) と `q` (ゲート) も使える。`@SW` / `@PE` / `D` はノイズには効かない (§3.1)。

### Q5. N1 と N2 の違い

N1 = PSG1 (左チャンネル出力) / N2 = PSG2 (右チャンネル出力)。同期源も異なる: **N1 は PSG1 の tone2 (= P3)、N2 は PSG2 の tone2 (= P6) と連動**。

### Q6. 実機 (.qdf) と Web プレビューで音は同じ?

演奏ロジック (MZSD → レジスタ書き込み) は実機ドライバと同一経路 (Z80 DRIVER モード) なので同じ。チップ出力の合成のみ Web 固有のエミュレーション (§5)。

### Q7. `@IN` は P3 / P6 で指定するのでは?

いいえ。**`@IN` はノイズトラック (N1 / N2) に書く**のが C# オリジナル (`MmlParser.AtNoise.cs`) と同一の仕様で、P3 / P6 に書くと警告になる (§3.4)。「P3 / P6 (トーン3) と連動する」**機能**を `@IN` が提供するため混同しやすい。連動時の音程は **N1 自身の音符**で指定する。
