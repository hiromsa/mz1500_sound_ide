# DCSG ノイズチャンネル仕様 (SN76489AN / @WN・@IN 2 系統)

MZ-1500 Sound IDE のノイズ制御には **2 系統のトラック / コマンド** が存在する。
本書はそのハードウェア・MML・ドライバ実装を貫く総合仕様。
MML コマンドの詳細な文法は [mml_reference.md](./mml_reference.md) §3.6 を参照。

| 系統 | トラック | コマンド | 音高指定 | 用途 |
|---|---|---|---|---|
| **専用ノイズトラック** | `N1` (PSG1) / `N2` (PSG2) | `@WN0` / `@WN1` | 音符で 3 段階 (`c`=低 / `e`=中 / `g`=高のシフトレート) | 打楽器・効果音 |
| **トーン 3 統合トラック** | `P3` (PSG1) / `P6` (PSG2) | `@IN0` / `@IN1` / `@IN2` | `cdefgab` の通常の音符で自由 | 音程に追従するノイズ / 硬いパルス波 |

| やりたいこと | MML の書き方 | 実際の音 |
|---|---|---|
| ドラム・スネア (定番の「シャー」) | `N1 @WN1` (+ `v` `l` `q`) | ホワイトノイズ (高さは c/e/g の 3 段階) |
| 高い金属音 (ハイハット代わり) | `N1 @WN0` | 周期ノイズ (金属的な「カンカン」) |
| **音階で高さが変わる硬いパルス波** (ファミコン風ベース・リード等) | `P3 @IN1 o4 c e g` | 周期ノイズ連動 (デューティ比の偏ったパルス波) |
| **音階に追従する白噪** (風・エンジンの駆動音等) | `P6 @IN2 o4 c e g` | ホワイトノイズ連動 (音程 × 16 のクロックで散る) |
| 統合を解除して通常の矩形波へ戻す | `P3 @IN0` | 丸い矩形波 (ノイズチャンネルを解放) |

**最重要**: `@WN` の高さは **3 段階のみ** (SN76489 のハードウェア制約)。音階どおりの高さが必要なら `P3` / `P6` の `@IN` (統合) を使う。

## 2. ハードウェア構成

### 2.1 MZ-1500 の音源構成とトラック割り当て

MZ-1500 は SN76489AN (DCSG) を 2 個搭載:

| デバイス | I/O ポート | 出力 | トラック割り当て (MZSD trackIndex) |
|---|---|---|---|
| PSG1 | 0xF2 | 左チャンネル | P1 (0), P2 (1), P3 (2), **N1 (3)** |
| PSG2 | 0xF3 | 右チャンネル | P4 (4), P5 (5), P6 (6), **N2 (7)** |

各 PSG は「矩形波 3ch + ノイズ 1ch」で構成され、**ノイズチャンネルは各 PSG の 4 番目 (ch3)**。
クロックは 3,579,545 Hz。

### 2.2 ノイズ生成回路 (LFSR)

SN76489AN のノイズは 16bit シフトレジスタ (LFSR) で生成:

- **ホワイトノイズ**: フィードバック = `bit0 XOR bit3` → 最大長系列 (周期 65535 ステップ)。「シャー」という広帯域ノイズ
- **周期ノイズ (Periodic)**: フィードバック = `bit0` (1 ビット循環) → **16 ステップ周期**の短い循環。シフトクロックを f とすると f/16 の「キーン」という金属音

出力は LFSR の bit0 (±1 の矩形)。

### 2.3 ノイズシフトクロック (rate)

LFSR を 1 ステップ進めるクロックはノイズ制御レジスタの下位 2bit (rate) で選ぶ:

| rate | シフトクロック | periodic の音の高さ |
|---|---|---|
| 0 | Clock/16 = 223.7 kHz | 約 14.0 kHz |
| 1 | Clock/32 = 111.9 kHz | 約 7.0 kHz |
| 2 | Clock/64 = 55.9 kHz | **約 3.5 kHz** (最も低い) |
| 3 | **tone2 周波数 × 16** (連動) | **音符の音程** と等しくなる |

- rate 0〜2 は「固定クロック」= 音程とは無関係
- **rate 3 が「3ch (P3/P6) との同期」**: 同一 PSG 内の tone2 (P3 または P6 の音程レジスタ) の出力で LFSR が駆動される。tone2 が音程 f で鳴っていれば LFSR は f × 16 でシフト → periodic の基本波 = f、white の散らばりも f に比例

### 2.4 SN76489 レジスタ (データポート 0xF2 / 0xF3 への書き込み)

| バイト値 | 意味 |
|---|---|
| `0xE0 \| (white << 2) \| rate` | ノイズ制御 (white: 0=periodic / 1=white、rate: 0-3) |
| `0xF0 \| att` | ノイズ減衰 (att = 15 - v、0=最大音量 / 15=無音、2dB/step) |
| `0x80 \| (2 << 5) \| (period & 0x0F)` | tone2 period 下位 (fine ラッチ) — 同期時の音程書き込み |
| `(period >> 4) & 0x3F` (bit7=0) | tone2 period 上位 (coarse データ) |

## 3. MML コマンドと内部フラグ

`@WN` (N1/N2 用) と `@IN` (P3/P6 用) は**対象トラックが異なる 2 系統のコマンド**であり、
どちらも MZSD バイナリ上は同じ `NOISECTL (0x0A)` 命令へ出力される (flags の意味はトラック種別で判別、§3.4)。

### 3.1 専用ノイズトラック (N1 / N2) — `@WN`

| コマンド | 機能 | NOISECTL flags |
|---|---|---|
| `@WN0` | 周期ノイズ (金属音) | bit0 = 0 |
| `@WN1` | ホワイトノイズ (**初期値**) | bit0 = 1 |

- 音高は音符の音程から **3 段階のシフトレート (hint) を自動選択**する (§3.3)
- 有効な他のコマンド: `v` (0-15)、`@VE` (音量エンベロープ)、`q`/`@q` (ゲート)、`o`/`<>`/`K` (音程 = シフトレートの段階)、`t`/`l`、`[ ]`/`L`
- 無効なコマンド: `@SW` / `@PE` / `D` (ノイズトラックの NOTE は tone2 を 1 回書くだけで、これらのフレーム進行は適用されない)
- `@IN` は N1/N2 では無効 (警告「@in はトーン 3 トラック (P3, P6) でのみ有効です」)

### 3.2 トーン 3 統合トラック (P3 / P6) — `@IN`

| コマンド | 機能 | NOISECTL flags |
|---|---|---|
| `@IN0` | 統合解除 (**初期値**)。通常の丸い矩形波へ戻り、ノイズジェネレータを解放 | 0 |
| `@IN1` | 周期ノイズ連動。デューティ比の偏った硬いパルス波 (ファミコン風の極太ベース・リード等) | 1 |
| `@IN2` | ホワイトノイズ連動。音階で帯域が変わるノイズ (風の音・エンジンの駆動音等) | 2 |

統合モード (`@IN1` / `@IN2`) 中の動作:

1. **音符の音程 (`cdefgab`) が自身の周波数レジスタ (tone2) へ書かれる** — 通常の P3/P6 演奏と同一経路 (ノイズシフトクロック = 音程 × 16)
2. **発音はノイズチャンネルへ切り替わる**: トラックの音量 `v` (0-15) はノイズ減衰レジスタへ適用され、**トーン 3 自体は無音化する** (減衰 15 =「トーン 3 がノイズに乗っ取られる」)
3. ゲートオフ / 休符でノイズ減衰も 15 へ戻る (`@VE` 適用中はエンベロープ値がノイズ減衰へ進行)
4. `@IN0` で統合解除 → ノイズチャンネルを無音化して解放し、以後は通常のトーントラックとして動作

- 波形は `@IN` の値だけで決まる (`@WN` との併用は不要。`@WN` は P3/P6 では無効・警告)
- `@SW` / `@PE` / `D` / `@VE` / `@v` など通常のトーントラックのコマンドはそのまま有効 (tone2 が動けばノイズクロックも追従する)
- **注意**: 統合中は同一 PSG のノイズチャンネル (N1 / N2) と減衰レジスタを共有する。N1 と P3 を同時に鳴らすと**後から書いた方が勝つ** (実機と同じ挙動)

### 3.3 専用ノイズトラックの分周ヒント (rate 0-2 の自動選択)

`@WN` 時 (連動なし) の音高は、ドライバが**音符の高さから rate を 3 段階で自動選択**する:

| 実装 | 判定 | 実用音域 (o1〜o10 ≈ 33Hz〜16.7kHz) での選択 |
|---|---|---|
| SourceInterpreter (`TrackSequencer`) | 音符周波数 < 40kHz → rate 2 / < 80kHz → rate 1 / else rate 0 | **常に rate 2 (55.9kHz)** |
| 実機ドライバ (`mzsd_driver.asm`) | tone period == 0 → 0 / == 1 → 1 / else 2 | **常に rate 2** |

つまり実用音域では rate 2 に丸められ、`@WN0` は約 3.5kHz 固定、`@WN1` はいつも同じ帯域の「シャー」になる。**これは実機 (.qdf) でも同じ挙動**。

> **注意**: C# 版オリジナルのリファレンス (`mz1500_sound_driver/mml_reference.md` §5.1) には
> 「音符 c〜d で Low / e〜f で Mid / g 以上で High が切り替わる」との記述があるが、
> C# 実装 (`TrackSequencer.cs` の `freq < 40000 ? 2 : freq < 80000 ? 1 : 0`) とは一致しない
> (実用音域では常に rate 2)。本 IDE は C# **実装**に準拠する。

### 3.4 MZSD バイナリ (NOISECTL flags) の構成

```
NOISECTL (0x0A) + flags (1byte)
  N1 / N2 トラック (slot 3 / 7):  bit0 = white (1 = white / 0 = periodic)         ← @WN
  P3 / P6 トラック (slot 2 / 6):  値そのもの = 0 (解除) / 1 (periodic) / 2 (white)  ← @IN
```

ドライバはトラック種別 (DCSG チャンネル番号 3 = noise / 2 = tone3) で flags の意味を判別する。
バイナリフォーマット自体は変更されておらず、旧形式との互換性は保たれる。

### 3.5 初期値 (演奏開始時 / @ 未指定時)

| トラック | 初期値 | 相当する MML |
|---|---|---|
| `N1` / `N2` | white (bit0 = 1) | `@WN1` |
| `P3` / `P6` | 統合解除 (0) | `@IN0` |

(`SourceInterpreter` は `noiseWhite = 1` / `noiseIntegrate = 0`、実機ドライバは `init_ch_regs` で
ノイズトラックのみ `CH_NOISE = 1` を設定)

## 4. MZSD ドライバ実装

### 4.1 NOISECTL 命令 (0x0A)

MML の `@WN` は N1 / N2 の、`@IN` は P3 / P6 のデータ列へ `NOISECTL (0x0A) + flags (1byte)` として出力される。
flags の意味は §3.4。複数回書けばその都度レジスタへ即時反映される。

### 4.2 処理フロー (両エンジン共通の概念)

```
MML "@WN1" (N1) ─┐
                 ├─> MmlParser ──> NOISECTL flags ──> ドライバ
MML "@IN1" (P3) ─┘                                     │
音符 NOTE ───────────────────────────────────────────> ├─ N1/N2: hint 計算 → 0xE0|white<<2|rate 出力
                                                       ├─ P3/P6 統合: tone2 へ period 書き込み (通常 NOTE 経路)
                                                       │             + ノイズ制御 0xE0|white<<2|3 出力
                                                       └─ 減衰: N1/N2 = ノイズ減衰 / P3 統合中 = ノイズ減衰 (tone2 は 15)
```

### 4.3 SourceInterpreter (`src/core/player/TrackSequencer.ts`)

- `NoiseCtl` 命令:
  - ノイズトラック → `noiseWhite` を更新し `applyNoiseMode()` = `setNoiseControl(white, hint)`
  - トーン 3 トラック → `noiseIntegrate` を更新し `applyNoiseIntegrate()`:
    - `@IN1` / `@IN2` → `setNoiseControl(mode === 2, 3)` (波形 / tone2 連動 rate 3)
    - `@IN0` → ノイズ減衰を 15 (無音化) に戻し `writeAttenuation()` でトーン 3 減衰を復帰
- `startNote` (ノイズ): `hint = freq < 40000 ? 2 : freq < 80000 ? 1 : 0` を更新 → `applyNoiseMode()`
- `startNote` (トーン 3): 通常どおり tone2 へ period 書き込み (`applyPitchFrame`)。統合中も同一経路でノイズクロックが駆動される
- `writeAttenuation`: 統合中 (`isDcsgTone3 && noiseIntegrate !== 0`) は `setAttenuation(3, att)` + `setAttenuation(2, 15)` (発音のノイズチャンネルへの切替)

### 4.4 実機ドライバ (`driver/mzsd_driver.asm`)

- `ev_noisectl`: flags を `CH_NOISE` へ保存後、ノイズトラックは `apply_noise` を即時呼び。トーン 3 (`CH_DCSG == 2`) は `apply_noise_integrate` を即時呼び:
  - 統合 ON: `0xE0 | (flags bit1 << 2) | 3` (flags 2 = white → bit2 / rate 3 = tone2 連動) を出力
  - 統合解除: ノイズ減衰 `0xFF` (無音) 出力 → `write_att` でトーン 3 減衰を通常へ復帰
- `play_dcs` (トーン NOTE): 通常どおり tone2 の fine / coarse を出力 (統合中も同一経路 = ノイズクロックの音程書き込み)
- `play_noise`: `note_dctbl` から period を取得 → hint 計算 (`p==0→0 / p==1→1 / else→2`) → `apply_noise` (`0xE0|white<<2|rate`) → `write_att`
- `write_att`: トーン 3 かつ `CH_NOISE != 0` (統合中) は **ノイズ減衰 (`0xF0|att`) に `CH_ATT` を出力し、トーン 3 減衰は `0xDF` (無音)**。それ以外は通常のチャンネル減衰
- 初期値 (`init_ch_regs`): ノイズトラック (slot 3 / 7) は `CH_NOISE = 1` (white)、それ以外は `0` (P3/P6 = 統合解除)
- 両エンジンの等価性は `Z80DriverEquivalence.test.ts` (全フレーム音源レジスタ比較) で検証済み

## 5. Web エミュレーション (DcsgChip) の固有実装

`src/core/chips/DcsgChip.ts` のノイズ関連は以下のとおり (C# オリジナルからの意図的差分を含む — 詳細は [web_core_port.md](./web_core_port.md) §3.1):

1. **LFSR は 16bit** (`bit15` 挿入、初期値 0x8000)。white = `bit0 XOR bit3`。
   - C# 版は AND フィードバックのため白噪が即無音化するバグ、および 15bit 化すると 63 ステップの短循環 (約 890Hz のブザー音) になる問題を修正した差分実装
2. **ノイズ出力に 2 段 1-pole LPF (8kHz) + RMS 補正 + DC ブロック (30Hz)** を実装。
   - シフトクロック (55.9〜223.7kHz) が音声ナイキスト (24kHz) を超えることで生じる標本化エイリアス (金属的な高音) を、実機のアナログ出力段相当に減衰する
3. 仮想キーボード (`src/utils/virtualSynth.ts`) のノイズは Web Audio 直結の別実装 (白噪 lowpass 8kHz / 周期ノイズは音符周波数中心の bandpass)。演奏経路 (PLAY) と音質基準を揃えてある

## 6. MML 記述例

```mml
; --- 専用ノイズトラック: ドラム (定番の白噪) ---
N1 @WN1 v12 l8 c c c c r

; --- 専用ノイズトラック: ハイハット風 (周期ノイズ + 短いゲート) ---
N1 @WN0 v6 q2 l16 cccc cccc

; --- トーン 3 統合: 音階で高さが変わる硬いパルス波 ---
P3 @IN1 v10 l4 o4 c d e f g
P3 o5 g f e d c            ; 波形指定は保持される (@IN1 の再記述は不要)

; --- トーン 3 統合: 音階に追従する白噪 (帯域が音程で変わる) ---
P6 @IN2 v10 l8 o4 cc ee gg

; --- 統合解除: 通常の丸い矩形波へ戻す ---
P3 @IN0 v10 l4 c d e f
```

実サンプル:
- `samples/mml_reference/psg/psg_noise_basic.mml` — @WN / v の基本
- `samples/mml_reference/psg/psg_noise_integrate.mml` — @IN 統合モードの応用

## 7. FAQ (よくある落とし穴)

### Q1. `@WN0` を o4 c e g と書いても高さが大きく変わらない

**仕様どおり**。専用ノイズトラックのクロックは固定分周 3 段階しかなく、実用音域では常に最も低い rate 2 (periodic ≈ 3.5kHz) に丸められる。実機でも同じ。音階どおりの高さが必要なら `P3` / `P6` の `@IN` を使う (§1, §3.2, §3.3)。

### Q2. `@IN1` を書いたのに波形が変わらない / `@IN` と `@WN` の違いは?

`@IN` は **P3 / P6 専用**で、波形も同時に決める (`@IN1` = periodic 連動 / `@IN2` = white 連動)。`@WN` は **N1 / N2 専用**の波形指定で、音階は追従しない。両者は対象トラックが異なるため組み合わせる必要はない。

### Q3. P3 で `@IN1` を書いたのに音が変わらない / 無音になる

統合モード中の発音は**ノイズチャンネル**から出る (`v` はノイズ減衰へ適用)。トーン 3 自体は無音化するため「音が消えた」ように聞こえる場合は、出力先がノイズチャンネルになっていることを確認する。また同一 PSG の N1 / N2 と減衰レジスタを共有するため、N1 が同時に鳴っていると後から書いた方が勝つ (§3.2)。

### Q4. ノイズの音量が変わらない / 変えたい

`v0`〜`v15` (15=最大)。`@VE` と `q` (ゲート) も有効 (`@IN` 統合中も含む)。`@SW` / `@PE` / `D` は N1/N2 (専用ノイズトラック) には効かない (§3.1)。

### Q5. N1 と N2 / P3 と P6 の違い

N1 = PSG1 (左チャンネル出力) / N2 = PSG2 (右チャンネル出力)。統合トラックも同様に P3 = PSG1 側 (N1 と同一ノイズを共有)、P6 = PSG2 側 (N2 と共有)。**P3 の統合と N1 の発音は互いに干渉する** (同一ノイズチャンネル)。

### Q6. 実機 (.qdf) と Web プレビューで音は同じ?

演奏ロジック (MZSD → レジスタ書き込み) は実機ドライバと同一経路 (Z80 DRIVER モード) なので同じ。チップ出力の合成のみ Web 固有のエミュレーション (§5)。

### Q7. `@IN` は P3 / P6 で指定するのでは? (旧仕様との関係)

**はい。`@IN` は P3 / P6 (トーン 3 統合トラック) に記述する**。かつては C# オリジナルと同じ「`@IN` を N1/N2 に書く」仕様だったが、SN76489 のハードウェア構成 (ノイズチャンネルは tone3 の周波数レジスタで駆動される) に基づき、トーン 3 トラック自身がノイズへ統合される 2 系統仕様へ改訂した (2026-09-08)。旧仕様の `N1 @IN1 @WN0 ...` 形式の MML は `P3 @IN1 ...` への書き換えが必要。
